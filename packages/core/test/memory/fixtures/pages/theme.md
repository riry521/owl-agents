# テストの落とし穴

## 概要
ことり家計簿の単体テストで繰り返し起きた、環境に依存する失敗をまとめる。テストは `pnpm test` で、CI は日本時間の深夜に走る。
- 集計は月の境目（毎月 1 日 0 時）で区切る
- テスト用の DB は毎回作り直す

## 決まりごと
- ★ 日時は `clock` を引数で受け取り、テストでは固定値を渡す。理由: 実時計に依存すると日付が変わると落ちる（W812）
- 並び順を確かめるときは、ソートのキーを明示してから比べる。理由: DB の返す順は保証されない（W790）

## 落とし穴
- ★ 月末のテストだけ落ちる → `new Date()` で当月を作っていた → 固定日時を注入する（W812, W815）
- 乱数のテストがまれに落ちる → シードを固定していない → テストの先頭でシードを渡す（W790）

## 手順
### 落ちたテストの切り分け
1. 同じテストを 3 回続けて実行する
2. 1 回でも通るなら、時刻・乱数・並び順の順に疑う
3. 原因を直したら、日付をずらして（`TZ` と固定日時）もう一度実行する
